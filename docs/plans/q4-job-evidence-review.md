# Q4 job-evidence review

Status: second local Q4 slice, 2026-10-11. Implementation and local verification passed. PLAN.md owns progress; release scope and distributed skill guidance are unchanged. Q4 remains partial.

## Implemented behavior

The editor’s Tailor for job dialog now confirms a target role, seniority and language before analyzing pasted posting text. These are candidate-confirmed context, not inferred seniority or a semantic role benchmark. The review extracts explicit requirement/preferred/responsibility sections or criterion lines and retains exact UTF-16 source quotes/spans. Identical normalized lines merge while preserving source occurrences; stable identifiers do not serve as cryptographic hashes. Required priority wins when the same line is also preferred; the candidate can override priority, which is labeled and clears prior proposal/evidence acceptance.

Criteria are bounded Zod objects with category, posting/candidate-review priority origin, normalized alternatives, duration and manual-review reasons. Simple OR alternatives permit any complete group; AND requires every recognized term in one excerpt. Mixed/unrecognized compound clauses abstain. Explicit aliases are separate from related technologies. Java does not match JavaScript; ambiguous Go/JS/TS/R, duration, complex qualification wording, unrecognized credentials and unsupported languages receive manual review rather than invented qualification support. These provisional rules have synthetic regression coverage, not recruiting-outcome or benchmark validation.

Only visible current-CV entry titles/descriptions/bullets supply evidence. Each cited excerpt retains section/entry/bullet or field identity and a source span. Sentence/clause separation prevents a verb in a different sentence from elevating a plain skill mention. A clean applied-work excerpt with every term in one alternative supplies direct text support; a skills/summary mention, incomplete compound or related technology is partial. Negated/learning claims cannot supply positive support. Education/certification text must name an exact credential without an in-progress qualifier; its actual award/validity still requires human confirmation. Hidden sections cannot support a criterion. Suspicious markup/instructions and non-English excerpts cannot supply automatic support; nothing is fetched or executed from candidate/posting text.

Required, preferred and unclear-priority groups show separate direct/partial/not-found/manual counts. Direct contributes 1 support unit, partial 0.5 and not-found 0; unknown is excluded from the denominator. Required weight is 2, preferred 1 and unclear 0 for ordering. No total percentage combines preferred mentions with missing required qualifications, no universal ATS score, and no hiring probability. Unscorable groups show Not enough information. Not found describes this CV text, not the candidate’s actual ability.

The report records rules 2026-10-11.q4.2, terms 2026-10-11.1, analysis time, current CV ID/revision and SHA-256 of posting/source snapshot. The snapshot binds contact, name, provenance, all sections and presentation; it ignores only updatedAt. Priority overrides are explicit in the current review and do not pretend to alter the original posting hash. This slice introduced a browser-local in-memory view. The subsequent [saved-history slice](q4-job-review-history.md) adds explicit account persistence without changing the matching rules.

## Reviewed operations and persistence

At most three deterministic proposals reorder whole existing bullets within the same entry, using only direct support with reviewed required/preferred priorities. Stable ties preserve existing order. Before/after previews show every unchanged bullet. The user accepts individual proposals and confirms the evidence before creating an independent variant. Rejecting/keeping current order unselects a proposal. No skill insertion, headline change, bullet trimming, metrics invention or model-generated replacement text is possible through this operation boundary.

Creation recomputes allowed permutations from the reviewed source, preserves every candidate fact/bullet/provenance/design and uses the existing repository’s independent-document save. The parent flushes pending changes and checks both current and latest saved source snapshots before saving. A deleted/changed source blocks creation. The local submit lock blocks duplicate clicks; unconfirmed saves retain the review/selection and the same pending variant ID for retry. A retry adopts an already committed variant only when its complete snapshot and revision match the pending reviewed operation; later changes refuse adoption. This handles a lost response without silently creating a duplicate. Existing account/session/owner boundaries remain authoritative for account storage. A temporary creation receipt allows undo only while the created variant is open and its saved revision is still untouched; undo removes the variant with revision checking and opens the latest original. Later variant edits prevent deletion. Workspace switches clear the receipt; reload closes the in-memory review/undo receipt.

This slice does not introduce a new AI provider request. Model-generated semantic coaching must use the existing server-owned proposal boundary in later work. The legacy cover-letter matcher, Master Vault fact migration and cross-resume evidence storage are not upgraded by this slice.

## Bounds and verification

Posting: 20,000 characters, 60 criteria and 2,000 characters per line; criterion alternatives and source occurrences are bounded. CV: 1,000 visible excerpts, 200,000 visible characters and a 4,000,000-character snapshot ceiling including presentation/contact data. Each criterion displays up to three supporting excerpts. Extremely large inputs fail clearly before creating a variant. Text is inert React-rendered content; the local operation accepts proposal IDs, not replacement strings or arbitrary mutation paths.

Eleven unit scenarios cover source spans/deduplication, bounds, OR/AND, explicit aliases/related terms, substring/punctuation cases, negation/aspiration, language/markup/credential/duration abstention, hidden evidence, separate denominators, source hashes, stale snapshots and exact permutation/fact preservation. Changing selected proposals also clears evidence confirmation. A textarea accessible-name issue when returning to input was fixed during verification.
